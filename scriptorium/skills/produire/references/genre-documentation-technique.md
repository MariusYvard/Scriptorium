# Playbook : documentation technique (cadre Diátaxis)

La documentation technique sert quatre besoins distincts. Le cadre Diátaxis les sépare : tutoriel, guide pratique, référence, explication. Mélanger deux modes dans un même document nuit aux deux.

## Quatre modes

- Tutoriel : apprentissage guidé, du point de vue de l'apprenant qui agit sous conduite.
- Guide pratique : résoudre un problème concret, pour un utilisateur déjà compétent, orienté tâche.
- Référence : description technique factuelle, neutre, exacte, exhaustive, sans interprétation.
- Explication : comprendre, le contexte et le pourquoi.

## Architecture et flux

Calquer l'architecture de la référence sur celle du code ou du produit décrit, ce qui rend les lacunes visibles. Sortir toute explication d'un tutoriel ou d'un guide : une digression casse la progression de l'utilisateur.

## Qualité

Viser d'abord la qualité fonctionnelle (exactitude, complétude, cohérence, utilité, précision), condition de la qualité profonde (adéquation au besoin, fluidité).

## Barre de qualité

- Chaque document tient un seul mode.
- La référence est exacte, complète, sans digression.
- Le tutoriel mène à un résultat, le guide résout une tâche.
- L'architecture de la référence suit celle du produit.
- Exactitude vérifiée contre le produit réel.

## Pièges à éviter

- Mélanger tutoriel et référence dans une même page.
- Une explication qui interrompt un guide pratique.
- Une référence incomplète ou périmée.
- Confondre guide pratique (tâche) et tutoriel (apprentissage).
